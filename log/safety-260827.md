### 6. Production Hotfix: Upload Photo Disappearance Bug (Live Client Blocker)
- **Incident**: Photos disappeared immediately upon upload on live production (`hitecapp-safety.web.app`) before entering captions.
- **Root Cause**: `get_company_plan_limits()` in `functions/main.py` omitted the `max_daily` key from its return dictionary, causing the Cloud Storage finalize trigger `onPhotoUpload` to crash with an unhandled Python `KeyError: 'max_daily'` on line 213. Consequently, newly uploaded photos remained stuck in `status: 'pending'` in Firestore, were ignored by the client's `where('status', '==', 'done')` listener, and were purged after 30s by the upload watchdog.
- **Fix Implemented**:
  1. Updated `functions/main.py` to return `max_daily` in all plan limit paths with safe `.get('max_daily', 100)` fallbacks.
  2. Enhanced `src/components/Dashboard.jsx` to display an explicit Alert Modal (`setAlertPopup`) whenever an upload is rejected by the server (e.g. `DAILY_LIMIT_REACHED`, `FILE_TOO_LARGE`) so photos never silently vanish without actionable assessor feedback.
- **Deployment**: Successfully deployed Cloud Functions (`onPhotoUpload`, `getSignedUploadUrl`, etc.) and Hosting to `hitecapp-safety` via Firebase CLI.

### 8. Production Hotfix: Report Download Failure in All Formats (DOC / PDF / PPT)
- **Incident**: Assessor team (Pak Bara) could not download generated reports in any format (PDF, PPT, or DOC) on both mobile and desktop views.
- **Root Causes & Solutions**:
  1. **Word / DOC (`.docx`)**:
     - *Bug*: In `Dashboard.jsx`, `onExportWordClick()` attempted to call `useExportWord(selectedProject, ...)(...)` inside an async click handler. Because `useExportWord` is a React Hook returning an object, invoking it inside an event handler violated React rules and threw `Minified React error #321 ("Hooks can only be called inside the body of a function component")`.
     - *Fix*: Replaced with the canonical standalone async function `handleExportWord` from `src/exportWordReport.js`.
  2. **PDF (`.pdf`) & PowerPoint (`.pptx`)**:
     - *Bug A (Client)*: `handleExport` called `getBestPhotoBase64(p)` without importing it, instantly throwing `ReferenceError: getBestPhotoBase64 is not defined` on the browser.
     - *Bug B (Cloud Function OOM)*: 2nd Gen Cloud Functions defaulted to `256 MiB` memory. Importing ReportLab, Pillow, python-pptx, and Google GenAI consumed ~240 MiB at startup; building documents exceeded 256 MiB (267–335 MiB used), causing Google Cloud Run to terminate the instance with OOM error.
     - *Bug C (GCS URL Signing)*: Cloud Run default credentials lacked RSA private keys to execute offline `blob.generate_signed_url(...)`.
     - *Fix*: Imported `getBestPhotoBase64` into `Dashboard.jsx`, upgraded Cloud Functions global options to 1GB memory (`options.MemoryOption.GB_1, cpu=1`) in `functions/main.py`, and adopted official Firebase Storage download security tokens (`firebaseStorageDownloadTokens: token`) for 100% reliable direct download URLs.

  - Full read-only Firestore audit conducted before and after all test runs.
  - Confirmed all 5 real client projects (`PT. Tirta Investama Citeureup Plant`) and all 6 photos, captions, F2 ATEX grades, and recommendations remained 100% untouched and intact.

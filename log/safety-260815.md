## 4. Desktop QA Triage Analysis

### A. Item 1: Step 11 & Code Version Confirmation
* **Code Version Under Test:** Confirmed running the **latest local codebase** with today's `combineProjects()` and `handleDeleteProject` fixes via the active Vite server (`http://localhost:5173`).
* **Root Cause of Step 11 Failure:**
  1. The deletion execution and `confirm()` modal were triggered and accepted (`[Dialog] confirm -> ACCEPT`).
  2. `deleteDoc` and `setProjects(prev => prev.filter(p => p.id !== deletedId))` executed.
  3. However, in `Dashboard.jsx`, the `<select>` element lacks a fallback `<option value="">` when `projects.length > 0` and `selectedProject` is `null`. In standard HTML, an unselected `<select>` without an empty option defaults visually to the first `<option>` in the DOM. Furthermore, `combineProjects()` snapshot callback defaulted `selectedProject` back to `merged[0]`.

### B. Item 2: Steps 7 & 8 Triage (Test Harness vs Real Bug)
* **Confirmed Test Harness Limitation:**
  * In desktop layout, the "Select Folder" button uses `<input webkitdirectory directory multiple />`.
  * Puppeteer's native `uploadFile` injects discrete file paths rather than folder streams, causing the browser's directory parser to ignore discrete file entries without triggering `onChange`.
  * When the test harness targeted the multi-file input without directory restrictions:
    * **Step 7 (AI Assessor observation/comments):** **PASS**
    * **Step 8 (Photo drag-handle reordering):** **PASS** (`[class*="drag-handle"]` selector verified)
  * **Conclusion:** Folder upload and drag-and-drop handles are functional in the product; the failure was strictly an automated test injection artifact.
